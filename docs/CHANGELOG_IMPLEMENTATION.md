# Журнал реализации Nutag

Этот файл хранит подробную историю реализации и продуктовых уточнений. Оперативный порядок работ находится в `IMPLEMENTATION_PLAN.md`, причины решений — в `docs/DECISIONS.md`, статус старой постановки — в `docs/REQUIREMENTS_AUDIT.md`.

## Журнал

- `e717c27` — зафиксировано архитектурное направление.
- `a5ab127` — добавлена сервисная проверка выбранных партий закупок и заготовок.
- `8871166` — добавлены правила сопровождения плана в `AGENTS.md`.
- `92ac080` — добавлена сервисная валидация источников строк закупки.
- `e6b334f` — план реструктурирован в operational roadmap.
- `pending` — добавлены сервисная проверка и UI-выбор выбранной партии готовой продукции в заказах, но работа по заказам отложена до стабилизации предыдущих этапов.
- `pending` — отчёт по движению закупочной партии перенесён в этап отчётов; форма заготовок защищена от базовых ошибок ввода и очищается после успешного сохранения.
- `pending` — добавлен учёт отходов по строкам ингредиентов в заготовках без изменения принципа партийного списания и расчёта себестоимости.
- `pending` — добавлена корректировка неиспользованных заготовок с блокировкой редактирования после использования в производстве.
- `pending` — добавлено удаление неиспользованных заготовок с текстовым подтверждением и сервисной блокировкой после использования в производстве.
- `pending` — улучшен выбор партий ингредиентов в заготовках: сначала выбирается ингредиент, затем конкретная доступная партия.
- `pending` — добавлен в план будущий учёт домашних нужд и домашних запасов как отдельный источник/направление движения партий.
- `pending` — на странице производства стоимость строки ингредиента отображается и пересчитывается по количеству вместо показа редактируемой цены.
- `pending` — добавлены нефасованный остаток готовой продукции, сервисная операция отдельной фасовки, списание упаковки при фасовке и тесты; фасовка ГП выделена отдельным этапом roadmap, а фасовка и упаковка убраны из этапа производства.
- `pending` — на странице производства стоимость списания ингредиентов и заготовок отображается единым read-only полем и пересчитывается на лету при изменении количества.
- `pending` — отдельный учёт отходов на этапе производства отклонён: отходы учитываются в заготовках, а производство фиксирует фактический нефасованный выпуск.
- `pending` — на странице производства выбор ингредиента/заготовки отделён от выбора партии: список партий фильтруется по выбранной позиции.
- `pending` — добавлены требования: не сохранять операции без обязательных трудозатрат; заменить ручной блок оборудования в производстве на модель ежемесячной амортизации с привязкой оборудования к готовой продукции.
- `pending` — уточнена модель амортизации для MVP: месячная амортизация считается автоматически из стоимости и срока службы оборудования, распределяется между продуктами пропорционально плановым месячным объёмам; ручные доли не входят в MVP, машино-часы отложены на будущее.
- `pending` — в этап экономики добавлен помощник расчёта цены продажи на основе плановой себестоимости, плановой амортизации, плановых объёмов и целевой маржи/наценки.
- `pending` — добавлена корректировка неиспользованных производственных партий с блокировкой после фасовки, повторной проверкой выбранных источников и пересчётом нефасованного выпуска.
- `pending` — добавлены требования: учитывать себестоимость расходных материалов и привести пользовательские идентификаторы партий/операций к единому формату.
- `pending` — ручной блок оборудования убран со страницы производства; новые партии создаются без ручной амортизации до реализации плановой экономической модели.
- `pending` — производственные партии нельзя создать или изменить без положительных трудозатрат; правило закреплено в сервисе, UI и тестах.
- `pending` — учёт расходных материалов в производстве отложен на будущее; добавлено удаление неиспользованных в фасовке производственных партий с текстовым подтверждением.
- `pending` — добавлена отдельная страница `Фасовка ГП`: новая фасовка выбирает нефасованный остаток и партию упаковки, считает выпуск и себестоимость на лету; история фасовок доступна для просмотра.
- `pending` — добавлено безопасное удаление неиспользованной фасовки с текстовым подтверждением; фасовка, уже использованная в заказах, заблокирована для удаления.
- `pending` — на странице `Фасовка ГП` добавлено отображение общей себестоимости фасовки, себестоимости одной фасовки и отдельной себестоимости базовой единицы для складских списаний.
- `pending` — форма нового заказа защищена от неполных строк и заказов без выбранной партии готовой продукции; сервис создания заказа теперь требует конкретную фасованную партию.
- `pending` — в форме заказа партия готовой продукции теперь выбирается после продукта и список партий обновляется сразу при смене продукта; размер фасовки и единица измерения подтягиваются из выбранной партии; в план добавлены workflow заказа, резервы, плановые партии и источник цены продажи.
- `pending` — исправлен сброс операционных данных: удаляются фасовки, фасованные партии и нефасованные остатки готовой продукции; складские сервисы и история фасовок защищены от старых осиротевших строк после некорректной очистки, такие строки не создают отрицательный остаток упаковки.
- `pending` — в план добавлены подсказки по статусам на странице заказов и требование не показывать полностью израсходованные позиции в обычных текущих остатках.
- `pending` — согласован workflow заказов для MVP: заказ резервирует выбранную готовую партию или фиксирует плановую потребность, а целевая модель отделяет резерв от фактического списания при статусе `Выдан`.
- `pending` — реализован базовый резерв готовых партий: складской сервис считает физический остаток, активный резерв и доступно к продаже; форма заказа показывает эти значения и проверяет доступно к продаже.
- `pending` — принято решение по хранению реальных данных: для MVP используется локальный SQLite вне папки проекта с backup перед миграциями; онлайн-режим отложен, но проект должен быть готов к будущему PostgreSQL через database URL.
- `pending` — в план добавлены заготовки из заготовок, уточнение смысла поля `Цена за фасовку` и запрет несовместимых статусов заказа/оплаты/резерва.
- `pending` — следующий шаг временно переключён на fast-track себестоимости: сначала оперативный отчёт фактической прямой себестоимости фасованных партий ГП, затем расчёт валовой маржи заказа; подсказки по статусам заказов остаются в backlog.
- `pending` — реализован fast-track отчёт фактической прямой себестоимости фасованных партий ГП на странице `Экономика`; добавлен сервисный расчёт и тест.
- `pending` — реализован fast-track расчёт валовой маржи заказов: строки используют себестоимость выбранной фасованной партии ГП, заказ показывает выручку, прямую себестоимость, доставку и валовую маржу без средневзвешенной подмены.
- `pending` — добавлены MVP-редактирование и удаление заказов: реквизиты, статусы, доставка, комментарий, количество и цена существующих строк редактируются с сервисной перепроверкой партий; удаление требует подтверждения и освобождает резерв/списание.
- `pending` — план переведён на двухслойную структуру `Execution Queue + Domain Backlog`; следующий шаг теперь выбирается из линейной очереди, а не из backlog-разделов по областям.
